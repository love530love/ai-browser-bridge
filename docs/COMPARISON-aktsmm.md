# 同名项目对照与可借鉴能力

GitHub 上的 [aktsmm/ai-browser-bridge](https://github.com/aktsmm/ai-browser-bridge) 是独立项目，并非本仓库的上游或同一实现。它更偏向“Chrome 扩展内的 LLM 助手”，公开说明包含文本模式、截图模式、混合模式、侧边栏、右键快捷操作、表单辅助和多种模型提供方。

## 值得借鉴的方向

- **文本 / 截图 / 混合模式**：为页面读取和复杂 Canvas 页面提供明确的模式选择。我们的 Bridge 已有 DOM、Debugger、截图和坐标适配器，后续可把策略选择统一成显式能力协商。
- **页面状态可见性**：将 ready、partial、unsupported、permission-required 等状态直接展示给用户。我们的 `doctor`、`browser_health` 和 waiting 合同应继续向可执行诊断演进。
- **高风险动作分级**：表单辅助默认停在提交前，下载只有确认完成才报告成功。可作为我们写事务和 `unknown` 状态验收的参考。
- **安装与开发验证说明**：对方 README 同时列出安装、设置、测试、隐私和限制，值得借鉴为本项目的公开文档结构。

## 不直接照搬的部分

- 对方以模型助手和侧边栏对话为核心；本项目以任意 Agent 的 MCP/HTTP/CLI 接入、队列、租约、离线执行和无人值守恢复为核心。
- 模型提供方、页面内容和用户隐私边界不同，不能直接复制其数据流或权限策略。
- 对方公开说明明确 Playwright/CDP 不是其自动接入后端；本项目将这些能力作为可选适配器和诊断通道规划。

## 对外定位

本项目不是同名项目的 fork，也不声称在所有浏览器能力上超过它。我们的差异化是：**本机授权、多 Agent 调度、模型可选、复杂网页分层兜底、写操作验证、断线恢复和可审计运行**。具体能力以 [README](../README.md)、[AGENTS.md](../AGENTS.md) 和 [产品路线图](PRODUCT-ROADMAP.md) 为准。
