# 扩展错误维护

0.5.18 修复了旧版只有 WebSocket 已连接才能上报错误的缺口。

## 保留与分析

1. 可捕获的 worker 错误先写入 Chrome 扩展 local storage `errorOutboxV1`，再尝试发送。
2. 成功配对后以及每 20 秒传输保活时重试补传。服务写入 `.local/logs/audit.jsonl` 成功后才发送确认；收到确认移除暂存。
3. 最多保留 100 条待发送事件，超限丢弃最旧事件并累计丢弃数。磁盘/存储故障及 worker 被立即终止仍可能丢失事件，不能保证每个 Chrome 内部错误都被捕获。
4. 同一事件在确认丢失时可能多次落盘，`node src/cli.js diagnose-upgrade` 的 usage 汇总按事件 ID 去重、显示分类及丢弃数。生成的分析保存在 `.local/upgrade-analysis.json`；该命令按需运行，不是自动修复代码的后台代理。
5. 默认保留来源、分类、时间和编号，不保留原始错误文本、网页 URL、输入值或完整堆栈。用户提供的完整诊断可另存 `.local/logs/incidents/`，不提交 Git。

## 修复和清理流程

- connection refused 说明当时端口不可连接，需结合服务日志诊断停止原因；不是扩展已损坏的充分证据。重连及已有服务看门狗处理可恢复连接问题，不自动重放业务写操作。
- 先归档错误证据，再部署、重载、检查 doctor 的版本及源码身份，然后验证实际调用。
- 清理 Chrome 扩展 Errors 页是管理界面动作，需要可用的桌面适配器及当前明确目标。不能以禁用开发者模式、关闭日志或删除浏览器配置来隐藏错误。
- Chrome 内部错误不能由普通扩展代码直接任意清除。此版本未实现自动点击 Clear all；工具不可用时应报告维护尚未完成，不能声称错误已清除。
- 清除后仍需观察是否复现。历史记录被清空不等于根因修复，出现新错误应重新归档和分类。

## 已验证与限制

测试覆盖离线保存、worker 重建补传、确认前保留、有限存储、悬浮后取消鼠标按下及表单值变化。像素级 canvas/iframe 内容检测、截图绑定和通用业务结果核验仍待完善。
