# 开发交接 · 扩展 0.1.1

用户随后明确要求默认可操作所有网站。0.1.1 manifest 声明所有 HTTP / HTTPS host 权限，`allSites` 缺失时默认 true，覆盖已有 0.1.0 配置；密钥与列表保留。面板可关闭此模式恢复列表限制。worker 和注入脚本同时执行该策略。连接状态改为 runtime 消息推送，不增加轮询；连接有 10 秒超时。0.1.0 本机桥接服务无需重启，协议兼容。

目标：用户自主控制的浏览器插件，让支持工具调用的 AI 经统一协议操作已授权网页。项目独立于 FlagGems-sglang 与 AutoGLM。

## 架构与不变量

AI → MCP stdio / CLI / HTTP → 127.0.0.1 HTTP 服务 → 已认证 WebSocket → MV3 worker → Chrome API / 隔离世界脚本。

- 两个随机令牌分别用于 AI 客户端与扩展配对；不放 URL、源码、日志或分发包。
- 所有网站模式和指定源列表只通过扩展 UI 配置，AI 工具没有更改权限的入口。所有网站模式仍只接受 HTTP / HTTPS。
- 每次 `read` 生成快照 UUID，引用保存在扩展隔离世界的 Map，页面不能通过伪造 DOM 属性创建 ref。
- 单个服务最多 1 个扩展连接、1 个运行命令、16 个等待命令；默认每个运行命令 20 秒超时。超时关闭连接、拒绝剩余队列，不自动重放。
- 连接仅在 worker 启动或用户点击时尝试；保活每 20 秒一次，不运行 AI。用户暂停持久化到 storage。
- `pageOperation` 必须自己捕获错误并返回 `__aibError`：Chrome 的 executeScript 不保证把注入脚本抛错传给调用者。回归测试覆盖过期 ref。
- 连接生命周期用 epoch 阻止异步设置读取引发的旧连接覆盖新连接。
- 本机日志不记录网页正文、输入文字、截图或 token。网页输出通过工具响应交给调用者。

## 已有证据

`npm test` 覆盖 HTTP 鉴权、Origin/Host 检查、WS 鉴权、参数验证、双客户端排队、断线和超时。

`npm run test:e2e` 使用真实 Chromium 加载 extension，经控制面板填写配对信息并保存，再通过 SDK MCP 客户端调用工具。独立 HTTP 客户端验证兼容接入。测试页面的聊天回显是本地夹具，**不是某个云 AI 平台的真实对话**。

最终测试结果查看 `output/playwright/e2e-report.json` 与 `docs/VERIFICATION.md`。如出现历史失败文件，按时间和版本区分，不把旧失败当成最新结果，也不要隐瞒偶发问题。

## 尚未完成

日常 Chrome 的人工安装/权限授予与配对需单独验证；不将测试 Chromium 的连接当成日常 Chrome 的连接。

首版限制见 README。优先后续工作：

1. 完成日常 Chrome 连接，选一个用户明确授权的真实网站验收读取与操作。
2. 加入按客户端/工作流的标签页租约，避免多步骤操作相互插入；明确租约失效和人工抢占语义。
3. 增加 iframe / Shadow DOM 的定位与引用作用域、页面状态变化检测。
4. 按需增加 CDP 可信输入；保持无任意 JS / shell 执行接口的默认边界。
5. 增加工具调用审批、操作预览、可取消的等待队列与事件订阅；已派发操作只报告取消的不确定性，不能声称撤销。
6. 外部 AI 回答流接入侧边栏；API 模型和网页对话模式分开。模型密钥只放本机服务，不放扩展页面。
7. 做站点兼容性矩阵与回归样本，比较具体任务成功率，不能仅凭功能列表声称全面超过 AutoGLM。

## 执行约定

所有 Windows shell 使用 PowerShell 7。项目 Node 22+；`npm ci` 使用锁文件。保持 `.local`、个人浏览器资料、测试临时配置和 `node_modules` 不进入源码分发包。普通用户聊天不得触发后台 AI 轮询。未经用户明确请求，不更新全局 memories。
