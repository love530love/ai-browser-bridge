# 浏览器工具链能力验收

目标是复杂页面和无人值守任务可靠完成。没有统一对照评测前，不宣称“世界最强”；工具数量和演示次数不等于完成率。

| 指标 | 验收方式 | 当前证据与缺口 |
| --- | --- | --- |
| 任务完成率 | 每个固定场景记录目标状态，不能仅检查点击已派发 | 本地 portal/表格/Shadow DOM 回读通过；HiDevLab 实页尚未验收 |
| 误操作 | 错行、遮挡、引用复用、重复提交的负向测试 | 行变化拒绝旧引用、透明遮罩拒绝点击已覆盖；实际业务重复提交仍需专门场景 |
| 并发与等待 | 多 agent、租约竞争、维护及客户端超时 | 串行队列与等待协议已有测试；已排队长请求的进度/取消仍待补齐 |
| 故障恢复 | 服务退出、扩展离线、写结果不明 | 守护恢复与等待指导已有实现；结果不明的写操作不自动重放 |
| 部署一致性 | 磁盘、服务、扩展代码身份与行为一致 | 服务新增 buildId 检查；扩展同版本源码身份仍待实现 |
| 可追溯性 | 每次验收独立报告，保留失败证据 | 本地独立运行目录、截图及分类汇总已实现；尚无长期统计仪表盘 |

每次报告应列出代码提交、服务/扩展版本、场景、预期结果、实际结果与未覆盖范围。故障注入必须单独统计；未知、被阻塞和跳过不能计作成功。耗时对比应使用相同机器、页面和网络条件，至少记录分位数而不是单次最快结果。

近期优先级：先完成部署一致性，再补长请求状态/取消；随后扩展嵌套框架、虚拟列表、固定列独立副本与组件视觉定位的真实场景。安全软件告警不以降低策略、恢复隔离脚本或换名执行方式解决。
