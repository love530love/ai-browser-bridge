# 浮层、坐标与交易结果可靠性

2026-10-24：根据用户提供的 VeryAI 操作记录审议，未在真实租用页面重放操作。记录中的历史遮挡根因尚未通过截图、命中测试与同时间布局数据确证。

## 当前实现

- `browser_click` 检查中心点命中，不能绕过遮挡。
- `browser_dismiss_overlay` 点击指定关闭控件并等待消失，不删除 DOM 背板。
- 0.5.17 的 `browser_prepare_coordinate` 在当前页面保存最多 32 个、15 秒有效的一次性目标凭据。`browser_action` 指针动作需带凭据；派发前比对元素、命中、几何、视口、滚动及所属弹窗前 8000 字符。失配返回 waiting，不派发。
- `browser_failure_help` 对遮挡返回截图、命中与坐标单位诊断；对 attemptedAction 中明确描述的租用、续租、付款返回 `transactionOutcome: unknown`、所需凭据及禁止自动重放标志。这是确定性建议，不会调用网站、判定订单结果或执行恢复动作。仅传通用工具名不能推断业务意图。
- MCP 初始化加载的操作契约要求核对容器、产品、数量、计费与价格，禁止按标签/几何列表顺序配对，禁止以库存变化、余额变化或按钮已点击作为订单完成证据。

## 验证边界

单元测试覆盖遮挡解释、租用结果未知、错误文本不能改变动作意图、离线诊断及禁止写重放。没有执行真实付费、租用、开关机操作，没有证明本次 VeryAI 页面已经修复。

0.5.17 需服务与扩展配套升级、重新加载扩展，MCP 客户端重新连接刷新工具列表。源码推送不代表正在运行的进程已升级。

坐标预检不与截图像素绑定，调用方仍需检查返回目标；校验与 CDP 派发之间存在短暂竞态，Swipe 只校验起点，iframe 内部及 canvas 图像变化尚无像素级验证。新增模拟页面测试覆盖同 URL 换产品、覆盖层、滚动、视口、过期与重复凭据；真实 Chrome 验收尚未完成。

## 下一步硬性保障与验收

1. 在已有目标凭据基础上增加截图绑定与 iframe/canvas 内部变化检测。
2. 为同名按钮增加可见对话框和容器约束；使用遮挡、固定列副本、隐藏 modal、异步换产品的本地夹具验证。
3. 增加显式业务后置条件及结果 `confirmed / unknown / rejected`；未确认不触发第二次提交。通用 UI 条件验证不能替代订单后端事实。
4. 在无真实费用的测试页验证从发现错误配置、重新定位到结果读取的完整流程，再进行授权现场验收。

这些项目仍待实现，不能作为现有能力宣传。客户端契约不能强制任意模型遵守，也不能保证第三方网站永不变化。

## 结果分叉与证据强度（2026-11-18，0.47.0）

赛事报名实测暴露的不是「点击没生效」，而是「验证条件问错了问题」：提交可能导航、行内报错、或只发请求，单一短语 `textAppears:"成功"` 还会被登录 toast 提前满足。0.47.0 的边界如下：

- `expect.anyOf` 表达「任一合法结果」，最多 6 个分支；`anyChange` 只证明「有变化」，不证明变化是本次动作造成的；`stableForMs` 只证明条件持续，不证明服务端已落库。提交类仍优先 `urlContains` + 落地页持久元素，toast 只作辅助。
- `outcome` 是派发后的判定：`navigated` / `dom_changed` / `condition_met` / `validation_error` / `no_change`。`validationErrors` 只在行内错误真实可见时出现；`no_change` 不等于「没发生」，只等于「页面可观察层没有变化」。
- `not_dispatched` + `matchedIn.isTransient:true` 表示命中的是残留提示，动作没有发出；应换条件，不得原样重试。
- `browser_eval_verified` 有完整页面权限，与 `browser_eval` 同层；账本记录的是「这次 eval 被派发且观察到了什么」，不是「eval 的内容安全」。
- `commandId` 只对「完全相同的参数」承诺幂等；改参复用返回 `command_id_params_mismatch`，旧结果不会被回放。账本在服务内存，重启后失效。
- `browser_capture_element` 是观察工具，不改变页面；元素必须在当前视口可绘制，滚出视口的先滚动再截。

仍未实现：`browser_ocr` 的 ref 范围识别、`browser_submit_verified` 之类的专用提交工具、幂等账本持久化，以及服务端落库事实的直接查询。通用 UI 条件验证仍不能替代订单/报名后端的最终事实。
