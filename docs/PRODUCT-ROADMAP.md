# AI Browser Bridge 能力路线图

本项目的目标是成为面向多 Agent、无人值守和复杂网页场景的可靠浏览器操控编排层。评价标准不是工具数量，而是系统能否在不同页面、并发和故障条件下自动选择策略、验证结果并恢复任务。

## 当前基线：0.5.7

以下能力已经纳入当前版本体系，并由 `npm run doctor` 检查：

- 本地 HTTP/WebSocket 桥接与 Chrome 扩展连接
- 服务与扩展版本匹配检查
- 44 个 MCP 工具的完整性检查
- 多 Agent 队列、优先级、等待状态和标签页租约
- 读操作超时隔离，避免拖垮桥接连接
- 写操作结果不确定时禁止自动盲目重放
- `browser_health`、`browser_tabs`、`browser_observe` 启动握手
- 页面读取、元素查找、动作准备和结果验证
- iframe/frame 引用路由
- 广告、弹窗、客服浮窗和遮挡层扫描
- 滚动容器和复杂页面的受限读取
- 上传目录限制和上传前授权检查
- 网络摘要、性能诊断和失败辅助信息
- 扩展重载、服务重启后的连接恢复基础机制
- 项目级 `AGENTS.md` 和 Agent 接入提示词

## 世界级浏览器操控目标

### 统一控制层

统一 Bridge、Chrome DevTools Protocol、Playwright、扩展脚本、截图和坐标操作，让 Agent 只描述目标，由系统选择执行通道。

### 页面理解层

融合 DOM、可访问性树、iframe、Shadow DOM、截图、元素几何信息、遮挡关系、网络状态、控制台错误和页面生命周期。

### 自适应定位层

按可靠性逐级选择语义定位、稳定属性、frame/Shadow DOM、几何分析、视觉定位和坐标操作，并为每次定位记录置信度和验证条件。

### 可验证事务

将操作统一为“观察 → 规划 → 执行 → 验证 → 完成或恢复”。点击、填写、选择、上传、下载和提交都必须有结果证据。

### 无人值守调度

支持任务持久化、断线续接、崩溃恢复、超时续租、暂停/继续、幂等操作和多 Agent 读写隔离。`waiting` 表示任务仍存活，不能被当作失败。

### 持续评测与适配

建立覆盖 SPA、iframe、Shadow DOM、Canvas、广告页、无限滚动、文件操作、重型数据表格、登录状态和并发冲突的真实网页测试集，并持续记录成功率、误操作率、平均延迟和恢复时间。

## 迭代原则

1. 稳定性优先于新增工具数量。
2. 默认配置应可直接使用，高级策略自动协商。
3. 读操作优先降级，写操作优先验证和保护。
4. 不确定结果不自动重放，先重新观察。
5. 所有版本更新同步维护 README、AGENTS.md、变更日志和本路线图。
6. 每个重要能力都要有可重复的诊断命令或回归场景。

## 下一阶段优先级

1. 高层 `browser_task` 目标接口和策略选择器。
2. DOM、视觉、坐标三路定位融合。
3. 页面状态机：加载中、可交互、遮挡、登录失效、网络异常和完成。
4. 任务队列持久化与重启恢复。
5. 复杂网页压力测试与无人值守回归套件。
6. 操作证据、失败原因和降级路径的统一审计记录。

本文件随每次版本迭代更新，已完成能力、当前限制和下一阶段目标必须保持一致。
