# AI Browser Bridge 能力路线图

本项目的目标是成为面向多 Agent、无人值守和复杂网页场景的可靠浏览器操控编排层。评价标准不是工具数量，而是系统能否在不同页面、并发和故障条件下自动选择策略、验证结果并恢复任务。

## 当前基线：0.5.22（2026-10-26）

以下能力已经纳入当前版本体系。`npm run doctor` 检查版本、连接、构建摘要和工具 schema；它不证明每项业务能力已完成现场验收。验证范围见 [部署记录](DEPLOYMENT-2026-10-26.md)。

- 本地 HTTP/WebSocket 桥接与 Chrome 扩展连接
- 服务与扩展版本匹配检查
- 51 个 MCP 工具的完整性检查
- 多 Agent 队列、优先级、等待状态和标签页租约
- 读操作超时隔离，避免拖垮桥接连接
- 写操作结果不确定时禁止自动盲目重放
- `browser_health`、`browser_tabs`、`browser_observe` 启动握手
- 页面读取、元素查找、动作准备和结果验证
- iframe/frame 引用路由
- 广告、弹窗、客服浮窗和遮挡层扫描
- 滚动容器和复杂页面的受限读取
- 上传目录限制和上传前授权检查
- 网络摘要、性能诊断和失败辅助信息
- 扩展重载、服务重启后的连接恢复基础机制
- 项目级 `AGENTS.md` 和 Agent 接入提示词

## 定位与能力边界

本项目不宣称在所有浏览器操控能力上超过 Playwright、Puppeteer、CDP 或 Chrome DevTools MCP。它的差异化目标是：在本机授权、多 Agent 并发、无人值守和故障恢复场景中，把这些底层能力编排成可验证、可恢复的执行系统。比较应以可复现的场景矩阵和指标为准，而不是工具数量或宣传口号。

能力采用组合式设计：Bridge 负责授权、队列、租约、策略和恢复；扩展负责页面内观察与交互；CDP 负责调试、网络和性能；视觉/坐标通道只作为有证据的兜底。每次降级都必须记录原因、置信度和验证结果。

## 世界级浏览器操控目标

### 统一控制层

统一 Bridge、Chrome DevTools Protocol、Playwright、扩展脚本、截图和坐标操作，让 Agent 只描述目标，由系统选择执行通道。

### 模型独立与离线可用

GPT、其他云端模型和本地模型都只能作为可选的规划、视觉理解或恢复决策器，不能成为任务执行的单点依赖。没有模型、模型用量耗尽、网络不可用或模型响应超时时，Bridge 仍必须依靠确定性工具链完成可识别的浏览器任务：能力探测、DOM/Accessibility、iframe、Shadow DOM、几何命中、遮挡分析、滚动、表单、上传下载和结果验证均由本地执行层提供。

模型接入采用能力协商和可替换适配器。模型只返回受 schema 约束的计划或候选定位，不能绕过租约、权限、origin、上传目录和写操作验证。模型离线时，任务进入本地策略路径、`waiting` 或可恢复检查点，不能丢失、失败退出或自动创建第二条浏览器通道。

### 对抗性与高风险网页

伪装页面、诈骗页面、色情页面、恶意广告页和脚本异常页面必须视为不可信输入。页面文本、按钮名称、隐藏元素、弹窗内容和模型可见截图都不能改变系统权限或安全策略。页面发出的“忽略规则”“复制密钥”“下载并运行”“关闭安全检查”等指令必须作为页面数据处理，不能作为 Agent 指令执行。

本地执行层需要提供导航 origin、下载目录和上传目录白名单，危险下载和外部协议拦截，跨源和受保护页面边界，敏感字段与 Cookie/Authorization 脱敏，脚本错误和网络异常隔离，弹窗与重定向上限，以及支付、登录、删除、外发消息、安装扩展和执行文件等高风险动作的明确确认或 `requires_user` 状态。视觉和坐标兜底必须先做遮挡、视口、来源和风险检查，不能用来绕过验证码、权限提示或网站安全机制。

对抗性网页回归场景至少覆盖覆盖式透明层、不断变化的按钮位置、伪造浏览器警告、恶意提示注入、循环弹窗、自动下载、重定向链、跨源 iframe、混淆脚本、广告点击劫持和敏感信息诱导。目标是安全停止并保留检查点，而不是在不确定时强行完成。

### 人类级操作与受保护界面

“任意 Agent 都能操作浏览器”分为两类能力：普通网页的完整操控，以及 Chrome 内部/桌面界面的受控操控。普通 HTTP/HTTPS 页面继续由 Bridge 通过 DOM、Accessibility、iframe、Shadow DOM、Debugger、截图和坐标适配器完成；`chrome://extensions`、`chrome://settings`、`chrome://inspect`、DevTools 内部页和 `chrome-extension://` 页面不能伪装成普通网页 DOM。

新增能力经纪层（capability broker）后，Agent 先提交目标和风险，再由本地策略选择执行通道：

```text
目标 → 风险评估 → 能力协商 → 预览计划 → 授权/检查点 → 单步执行 → 证据验证 → 完成/恢复
```

能力矩阵：

| 等级 | 示例 | 默认策略 |
|---|---|---|
| L0 | 读取、截图、滚动、查找元素 | 自动 |
| L1 | 点击、填写、选择、受限下载 | 自动并验证 |
| L2 | 上传、表单提交、跨 origin 导航 | 白名单内自动，否则等待 |
| L3 | 登录、外发消息、发布、删除 | 预授权或明确确认 |
| L4 | 重载/安装扩展、开启开发者模式、修改浏览器安全设置 | 每次确认，默认禁止自动 |
| L5 | Cookie/密钥、任意文件、系统命令、绕过安全机制 | 禁止或独立人工流程 |

受保护界面适配器的优先顺序是 Computer Use/桌面 UI 自动化、专用隔离 Chrome 实例和 Native Messaging；Native Messaging 只负责受白名单约束的生命周期与诊断，不能成为任意 Shell 或绕过 Chrome 安全边界的后门。每个动作必须校验窗口标题、目标 URL、扩展 ID、截图/版本证据、一次性 nonce、Agent 身份和幂等键。

新增目标工具：`browser_capabilities`（能力和限制握手）、`browser_policy_check`（风险与所需授权）、`browser_privileged_ui`（受限内部界面动作）、`browser_task_checkpoint`（长任务检查点）、`browser_verify_state`（版本/连接/下载/表单证据）和 `browser_audit_query`（解释等待、拒绝和未知状态）。保护页面不能被误报为普通 DOM 成功；不支持时必须返回 `requires_user` 或 `unsupported_with_reason`。

### 页面理解层

融合 DOM、可访问性树、iframe、Shadow DOM、截图、元素几何信息、遮挡关系、网络状态、控制台错误和页面生命周期。

### 自适应定位层

按可靠性逐级选择语义定位、稳定属性、frame/Shadow DOM、几何分析、视觉定位和坐标操作，并为每次定位记录置信度和验证条件。

### 可验证事务

将操作统一为“观察 → 规划 → 执行 → 验证 → 完成或恢复”。点击、填写、选择、上传、下载和提交都必须有结果证据。

### 无人值守调度

支持任务持久化、断线续接、崩溃恢复、超时续租、暂停/继续、幂等操作和多 Agent 读写隔离。`waiting` 表示任务仍存活，不能被当作失败。

### 持续评测与适配

建立覆盖 SPA、iframe、Shadow DOM、Canvas、广告页、无限滚动、文件操作、重型数据表格、登录状态和并发冲突的真实网页测试集，并持续记录成功率、误操作率、平均延迟和恢复时间。

所有场景必须至少运行两次：一次启用外部模型增强，一次完全禁用 GPT/云端模型。后者仍需验证任务不丢失、工具链不阻断、写操作不盲目重放，并能在确定性路径上完成或返回明确的可恢复状态。

### 高层目标执行与策略选择

新增 `browser_task` 级别的目标接口，让 Agent 描述“找到并提交表单”或“下载满足条件的文件”，由服务端生成可暂停的步骤图。策略选择器根据页面能力探测结果，在 DOM、可访问性树、iframe、Debugger、视觉和坐标通道之间选择路径；Agent 仍可查看和接管计划，系统不会把高风险动作隐藏成不可解释的黑箱。

### 证据、幂等与恢复

每个动作必须带前置快照、动作证据和后置验证。上传、提交、删除、支付等不可逆动作需要明确的幂等键、结果状态（成功/失败/未知）和恢复建议；未知结果禁止自动重放。服务重启、扩展重载和电脑唤醒后，从持久化任务日志恢复到最近安全检查点，并保留人工接管入口。

### 安全与数据边界

默认保持本机监听和显式授权；远程使用必须经过独立的认证、来源限制、审计和最小权限网关。页面内容作为不可信输入处理，工具输出支持内容边界和敏感字段脱敏。上传路径、下载目录、导航 origin、写工具和模型裁决应可按 Agent 分权，并在审计日志中保留决策原因。

## 迭代原则

1. 稳定性优先于新增工具数量。
2. 默认配置应可直接使用，高级策略自动协商。
3. 读操作优先降级，写操作优先验证和保护。
4. 不确定结果不自动重放，先重新观察。
5. 所有版本更新同步维护 README、AGENTS.md、变更日志和本路线图。
6. 每个重要能力都要有可重复的诊断命令或回归场景。

## 交付门槛与衡量指标

每个版本只有在以下证据齐备后才标记完成：

- 连接恢复、版本错配、扩展重载和服务崩溃场景均有自动回归。
- 复杂页面矩阵覆盖 iframe、Shadow DOM、遮挡、内部滚动、虚拟列表、文件操作和并发写入。
- 每个写动作都有成功/失败/未知三态验证，未知结果没有自动重放。
- 记录任务完成率、误操作率、P95 延迟、恢复时间、队列公平性和数据泄露检查结果。
- 文档、README、AGENTS.md、CHANGELOG、doctor 输出和 MCP schema 同步更新。
- 外部模型不可用时，核心回归场景仍可完成或安全恢复；模型不是运行前置条件。

## 2026-10-15 场景审议：缺口与验收指标

### 无人值守

当前基础的重连和等待机制还需要变成可恢复的任务系统。任务应有持久化状态、幂等键、心跳租约、断点和最后一次页面证据；服务或扩展重启后要能从安全检查点继续，而不是重新执行可能已经成功的写操作。后台运行时不得打开设置页、弹出重复窗口或要求用户复制配对信息。

验收目标：服务重启后未完成任务 60 秒内恢复；扩展 Service Worker 休眠后自动恢复连接；连续运行 8 小时不出现重复任务；不确定写操作 100% 标记为 `unknown` 并暂停在可恢复检查点；所有终止任务都有可读原因和下一步建议。

### 多 Agent 并发

同一标签页的读操作可以合并或并行，写操作必须按资源和页面状态串行化。冲突返回存活的 `waiting` 任务并提供位置、预计等待和取消句柄；不能让 Agent 把排队误判为失败后自行创建第二条通道。调度器需要防止低优先级任务长期饥饿，也要限制单个 Agent 占满队列。

验收目标：20 个 Agent、100 个混合读写任务下，队列不丢任务、不重复执行；读任务 P95 等待时间小于 2 秒（页面本身阻塞除外）；高优先级任务 10 秒内获得调度；每个任务重启后仍能查询；租约过期后资源在 5 秒内可回收；相同幂等键最多产生一次外部写入。

### 重型和异常网页

读取不能把整棵 DOM 当成一个不可中断操作。需要阶段化预算：页面生命周期、可访问性树、候选元素、文本和网络摘要分别计时，并在预算耗尽时返回部分结果与继续游标。对广告、透明遮挡、固定浮窗、客服、引导层、嵌套 iframe、Shadow DOM、虚拟列表、滚动容器、Canvas 和跨域 frame 要说明发现范围和不可访问边界。视觉或坐标兜底必须先取得新截图、检查坐标和遮挡，并在动作后验证。

验收目标：在 10 类重型场景中，读取 P95 在 20 秒内返回完整或明确的部分结果；页面主线程繁忙时桥接仍保持连接；遮挡扫描能识别并报告覆盖目标的元素；滚动和下拉操作至少返回前后状态证据；跨域 iframe 不得被误报为可操作；所有坐标动作记录视口、设备缩放和截图哈希。

### 小白用户体验

默认安装后应能启动服务、加载扩展并自动发现版本，不要求用户理解配对、端口、租约或 MCP。失败页要显示“当前是否在线、下一步做什么、是否会影响正在运行的任务”，而不是只展示堆栈。历史错误应与当前状态分开；恢复后应显示已恢复并提供一键诊断。高级策略可以配置，但默认策略必须安全、可逆、低打扰。

验收目标：新用户在没有阅读开发文档的情况下 3 分钟内完成首次连接；连接恢复不新开设置窗口；`doctor`、状态页和 Agent 返回的版本、连接、队列结果一致；常见故障都有一条可执行修复建议；清理历史错误不会删除审计记录。

### 统一质量门槛

每次版本升级至少运行：静态页、SPA、重广告页、嵌套 iframe、Shadow DOM、虚拟滚动列表、文件上传下载、登录过期、扩展休眠、桥接重启和 20 Agent 并发场景。报告成功率、误操作率、P50/P95 延迟、恢复时间、任务丢失数、重复写入数和用户需手动介入次数。没有这些数据时，只能称为“实现了功能”，不能称为“稳定可用”。

## 能力边界与比较原则

本项目不应宣称在所有浏览器操控能力上超过 Playwright、Puppeteer、CDP 或其他方案。它的目标优势是把这些通道编排为可授权、可验证、可恢复的多 Agent 本地执行层。对外比较必须按具体场景和上述指标进行，并保留未支持页面能力、浏览器版本和权限条件。

本文件随每次版本迭代更新，已完成能力、当前限制和下一阶段目标必须保持一致。

## 下一阶段交付顺序与验收门槛

1. DevTools 状态机：识别是否已打开、绑定被检查标签、仅在确认关闭时打开一次，验证面板和目标。F12 按键派发不算成功。
2. 设置页适配器：逐项读取当前值、执行用户指定变更、回读验证，并为可逆设置保留恢复值。不得把规划器当执行器。
3. 下载闭环：关联用户目标、触发动作、Chrome 下载 ID、完成/中断状态和本地文件证据；未知状态先核对，禁止重复下载写入。
4. 扩展管理：安装、移除、开发者模式分别实现精确目标、授权范围和前后状态验证，复用当前 Chrome。
5. 统一结果及场景矩阵：分别标注已实现、已实测、部分实现、未实现；返回成功、等待、未支持或结果未知，区分未派发和可能已派发。

上述为开发目标，当前除固定项目扩展 Reload 外，尚未实现通用内部设置与 DevTools 执行平台。不得将目标列表写成已交付能力。
