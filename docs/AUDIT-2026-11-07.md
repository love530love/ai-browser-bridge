## 4. 测试盲区（本轮已补 9 条，`test/heartbeat.test.js` 13 → 22）

730 条全绿时仍存在的盲区，按危害排序：

1. **异常轮产物没有渲染后文本断言**——唯一读 incident 文本的断言匹配的是恒定尾注，抓不到 B1。新增断言：报告含 `- verdict: **<实际值>**`、不含 `**undefined**`、含 `provenClean: false` 与具体 code。
2. **新模块不打真实边界**——`probeStatus`（真实 `fetch /status` + Bearer + `AbortSignal.timeout`）、`defaultReload`（`POST /call` 的 confirmation/hostId）、`defaultRestart` 全被注入绕过。新增 stub fetch 断言 URL/header/signal，以及 `/call` body 契约断言。
3. **开关缺「开与关不同」断言**——`--no-remediate` 只测 parse，`--dry-run` 只测开侧。新增 `remediate:true→executed` vs `false→remediation_disabled`、dry-run 不调用 restartFn 的对照。
4. **watch 接线 / 锁损坏 / 降级**未测。新增：watch 首轮不冻结、第二轮才冻结；半写锁可接管；`connected` 派生自 hosts[] 的健康判定。
5. **B3/B4 回归**：无 host 落后时不产出 action、一次采集失败不清空计数。

仍待补（列入排期）：`describeErrorList` 经 `b.call('browser_reload_extension')` 的端到端投影断言；隐藏文档下 rAF 兜底的运行时断言（现仅静态正则）。

## 7. AAR

- **事实**：四路审计独立复现了同一个历史坑（异常轮报告字段），并发现 5 个 0.37.x 真实缺陷；730 条全绿没有覆盖渲染后文本、真实 HTTP 边界、开关对照与 watch 接线。基线本身干净（git/版本/doctor/心跳全绿、incidents 全部闭环）。
- **偏差**：① 上一版发布时把「CLI 输出正确」当成「所有产物正确」，没检查只在异常轮生成的 markdown；② 常驻 watch 与 hourly 单次巡检被当成同一种 cadence；③ 文档里保留「两处版本」「Canary/Default」「可换 Playwright」等过时结论，正是 Agent 迷路的来源；④ 内部评分表写了不存在的工具名且不抛错，等于静默失效。
- **改进**：凡「只在异常轮生成」的产物必须有渲染后文本断言；凡「新增模块」必须有一条走真实边界的测试；去抖状态机要检查「采集失败时证据会不会被清空」；watch 首轮不与历史 cadence 比较；任何「不支持 / 两处 / 正确答案」类措辞都要定期与代码对账。已全部写入 `docs/DEVELOPMENT-GUIDE.md` 与 `.workbuddy-ai/memory/MEMORY.md`。
